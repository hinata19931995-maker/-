# Competitive Benchmarking

## Objective

Turn competitor research into measurable product-development benchmarks.

Benchmarking is not a one-time comparison chart. It should support product definition, PRD targets, EVT/DVT testing, launch readiness, and next-generation planning.

## Benchmark Set

Maintain a focused set of benchmark products, normally 5–10 when possible.

Represent:

- Market leader
- Price leader
- Feature leader
- Design leader
- Strong user-satisfaction product
- Emerging challenger
- Direct substitute

Select products because they answer a decision question, not because they are famous.

## Benchmark Questions

For each product ask:

1. What user job is this product optimized for?
2. What is its positioning?
3. What are its category-entry requirements?
4. Where does it deliberately win?
5. Where does it accept weakness?
6. Which complaints repeat?
7. Which positive attributes repeat?
8. What should our product match?
9. What should our product beat?
10. What can our product intentionally ignore?

## Benchmark Categories

Use relevant categories only.

### Performance
- Charging speed
- Power
- Latency
- Throughput
- Runtime
- RF range

### Thermal
- Surface temperature
- Device temperature
- Thermal throttling
- Cooling behavior

### Acoustic
- Fan noise
- Coil whine
- Beeps
- Mechanical noise

### UX
- Setup time
- Alignment
- Visibility of status
- One-hand use
- Control logic
- Nighttime disturbance

### Mechanical / ID
- Size
- Weight
- Stability
- Materials
- Finish
- Cable routing
- Port placement

### Compatibility
- Device range
- Case compatibility
- OS / protocol compatibility
- Accessory compatibility

### Reliability
- Drop
- Mechanical life
- Cable bending
- Connector durability
- Charging cycles

### Commercial
- Price
- Included accessories
- Warranty
- Packaging
- Bundle strategy

## Competitive Requirement Classification

For every major benchmark attribute classify:

- Category Entry Requirement
- Must Match
- Must Win
- Acceptable Lag
- Irrelevant

This classification should influence PRD priorities and cost allocation.

## Test Discipline

When physically benchmarking products:

- Use the same devices where possible
- Use the same power source when appropriate
- Use controlled ambient conditions
- Define start state
- Define test duration
- Repeat measurements when variability is meaningful
- Record firmware / software versions when relevant
- Record test setup and instruments

Do not compare numbers from incompatible test methods without qualification.

## Benchmark Record

Record:

- Product
- Model
- Market
- Purchase / observation date
- Firmware / revision if known
- Test method
- Result
- Source
- Confidence
- Notes

## DVT Competitive Gate

Before DVT exit, answer:

- Have category-entry requirements been met?
- Have Must-Match targets been met?
- Have Must-Win targets been demonstrated?
- Are Acceptable-Lag areas still acceptable to the positioning?
- Did any competitor launch materially change the benchmark?

If a Must-Win promise cannot be demonstrated, either fix the product or change the positioning before launch.

## Benchmark Change Control

Do not move targets casually after testing begins.

If benchmark targets change, record:

- What changed in the market
- Why the target changed
- Cost / schedule impact
- Product-positioning impact
- Approval decision

## Output

A useful benchmark report should include:

1. Benchmark Product Set
2. Benchmark Objective
3. Test Matrix
4. Results
5. Category Entry Requirements
6. Must Match
7. Must Win
8. Acceptable Lag
9. Key Competitive Gaps
10. Risks
11. Decision / Next Actions
